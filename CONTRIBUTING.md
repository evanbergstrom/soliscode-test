# Contributing to SolisCode Test

Thank you for wanting to help. This page is a short entry point. The details are in the [Developer guide](docs/developer-guide/README.md).

## Ways to contribute

- Report a bug or ask for a feature in an [issue](https://gitlab.com/soliscode/soliscode-test/-/issues). Say what you did, what you expected, and what happened, with the version you use.
- Improve the documentation. See [Documentation standards](docs/developer-guide/contributing/documentation.md).
- Fix a bug or build a feature. Open an issue first, so that the approach is agreed before you write code. The labels an issue can have are in the project file, `.claude/soliscode-project.md`, and in [Issue triage](docs/developer-guide/maintainers/triage.md).

## Your first merge request

Until a lawyer has reviewed the [contributor licence agreement](CLA.md), no contribution from anyone but the copyright holder is merged, even with a signed agreement. An issue is welcome meanwhile.

1. Set up your environment: [Development environment](docs/developer-guide/getting-started/dev-environment.md).
2. Follow the [contribution workflow](docs/developer-guide/contributing/workflow.md).
3. Make sure the full build passes: [Running tests](docs/developer-guide/getting-started/running-tests.md).
4. Open a [merge request](https://gitlab.com/soliscode/soliscode-test/-/merge_requests) from your fork, and fill in its template.

## Legal

SolisCode Test is licensed under the [Apache License 2.0](LICENSE.txt). Every new source file starts with the copyright header. Every outside contribution needs a signed [SolisCode Individual Contributor License Agreement](CLA.md) before it is merged. [Commit conventions](docs/developer-guide/contributing/commit-conventions.md#the-cla) says how to sign it.

## Security problems

Don't describe a security problem in a public issue. See [Security response](docs/developer-guide/maintainers/security.md) for how to report one.
